# T0: лексер, парсер, AST и вывод типов локальных

Контрольная точка T0 проекта (компилятор Funny). Свой код здесь минимален: этап собирается из домашних заданий, которые подключены через `:source-paths` (`../hw1/src`, `../hw2/src`, `../hw3/src`). Исправления в HW1–HW3 автоматически попадают в T0.

| Требование T0 | Откуда |
|---|---|
| Лексер | [hw1](../hw1) — `hw1.lexer` (ДКА, позиции токенов) |
| Парсер, AST, ошибки с позициями и восстановление | [hw2](../hw2) — `hw2.parser`, [грамматика](../hw2/grammar.md) |
| Проверки имён/типов, запрет записи в параметры, вывод типов локальных | [hw3](../hw3) — `hw3.types` |
| Обессахаривание `a[i] = v` → `a = set(a, i, v)` | здесь: `t0.pipeline/desugar` |

## Запуск

Из каталога `t0`:

```sh
lein test
lein run -m t0.main examples/ok.funny             # :desugared + :errors
lein run -m t0.main examples/ok.funny tokens      # или ast | desugared | errors
```

Код возврата 1, если есть ошибки (синтаксические — `:phase :syntax`, семантические — `:phase :semantic`, все с `:line`/`:column`).

## Обессахаривание

`desugar` заменяет узлы `:array-update` явным присваиванием с вызовом `set`: `a[i] = v` → `a = set(a, i, v)`; для нескольких индексов `a[i][j] = v` → `a = set(a, i, set(a[i], j, v))`. Узел помечается `:desugared-from :array-update`. Проход выполняется после проверки типов, поэтому новые узлы уже аннотированы `:type`. `set` — внутреннее имя семантики, а не публичный API.

## Тесты
