# HW1: краткий отчёт

## Токены

| Токен | Регулярное выражение |
|---|---|
| Пробелы и переводы строк (пропускаются) | `[ \t\r\n]+` |
| Комментарий (пропускается) | `//[^\r\n]*` |
| Целое число | `0|[1-9][0-9]*` |
| Идентификатор | `[A-Za-z_][A-Za-z0-9_]*` |
| Ключевые слова | `function`, `returns`, `uses`, `requires`, `ensures`, `while`, `if`, `else`, `true`, `false`, `assert`, `assume`, `invariant`, `length`, `int`, `not`, `and`, `or` |
| Операторы и разделители | `==`, `!=`, `<=`, `>=`, `->`, `+`, `-`, `*`, `/`, `<`, `>`, `=`, `,`, `;`, `:`, `(`, `)`, `[`, `]`, `{`, `}` |

Ключевые слова и операторы распознаются как буквальные строки. При совпадении выбирается самый длинный токен; при одинаковой длине используется приоритет из таблицы правил лексера. Поэтому, например, `ifx` является одним идентификатором, а `if` — ключевым словом.

## Автомат

Все правила объединяются в НКА Томпсона, затем subset construction строит ДКА, а алгоритм Хопкрофта минимизирует его.

| Показатель | Значение |
|---|---:|
| Состояния ДКА до минимизации | 113 |
| Состояния ДКА после минимизации | 110 |
| Алфавит | ASCII, 128 символов |

Таблица задаёт переход для каждого символа ASCII, включая переходы в ловушку. Ловушка — непринимающее состояние для продолжения, которое не соответствует ни одному токену; при сканировании переход в неё завершает поиск токена, а если подходящий токен не найден, лексер сообщает ошибку с позицией. Символы вне ASCII сразу дают лексическую ошибку.

## Набор тестов

Тесты проверяют ключевые слова и идентификаторы, максимальную длину совпадения, числа с ведущими нулями, пробелы и комментарии, ASCII-границы, построение и минимизацию автомата. Команды запуска приведены в [README](README.md).
