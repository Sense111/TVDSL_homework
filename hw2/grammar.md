# HW2: грамматика подмножества Funny

Парсер реализован методом рекурсивного спуска и строит AST в виде Clojure-карт с тегом `:node`. Ниже описано подмножество Funny, поддерживаемое в этом задании. Семантическая проверка и проверка типов не выполняются.

~~~ebnf
program       = function { function } ;
function      = [ "function" ] identifier "(" [ variable { "," variable } ] ")"
                [ "requires" expression ]
                "returns" variable { "," variable }
                [ "ensures" expression ]
                [ "uses" local { "," local } ] statement ;
variable      = identifier ":" type ;
local         = identifier [ ":" type ] ;
type          = "int" | "int" "[" "]" ;
statement     = block | assignment | if | while | assert | assume ;
block         = "{" { statement } "}" ;
assignment    = identifier assign-rest ;
assign-rest   = { "[" expression "]" } "=" expression ";"
              | { "," identifier } "=" call ";" ;
if            = "if" "(" expression ")" statement [ "else" statement ] ;
while         = "while" "(" expression ")" [ "invariant" expression ] statement ;
assert        = "assert" expression ";" ;
assume        = "assume" expression ";" ;
call          = identifier "(" [ expression { "," expression } ] ")" ;

expression    = implication ;
implication   = or [ "->" implication ] ;
or            = and { "or" and } ;
and           = not { "and" not } ;
not           = "not" not | comparison ;
comparison    = additive [ compare-op additive ] ;
compare-op    = "==" | "!=" | "<=" | ">=" | "<" | ">" ;
additive      = multiplicative { ( "+" | "-" ) multiplicative } ;
multiplicative = unary { ( "*" | "/" ) unary } ;
unary         = "-" unary | primary ;
primary       = integer | "true" | "false"
              | "(" expression ")"
              | ( identifier | "length" ) [ "(" [ expression { "," expression } ] ")" ]
                { "[" expression "]" } ;
~~~

Пояснения к грамматике:

- Общий префикс `identifier` у обоих вариантов присваивания вынесен (левая факторизация), как в коде: парсер читает список целей `identifier { "[" expression "]" }` через запятую, затем `=` и выражение, и только после этого проверяет форму. Кортежное присваивание `x, y = f(...)` допускает только неиндексированные цели и вызов справа; иначе сообщается ошибка с позицией.
- `length(xs)` разбирается как вызов с именем `length`; индексирование `{ "[" expression "]" }` применяется к имени, вызову и результату предыдущего индексирования.
- Неоднозначность `else`: `else` относится к ближайшему `if` (после then-ветки парсер жадно проверяет `else`).
- Пустой ввод (и ввод без единой функции) является ошибкой: `program` содержит минимум одну функцию.
- Сравнение неассоциативно: `a < b < c` не разбирается как одно выражение (после первого сравнения оператор остаётся необработанным и вызывает ошибку у вызывающей конструкции).

Приоритет операторов выражений от наивысшего к низшему:

~~~text
основное выражение/индекс/вызов → унарный минус → * / → + - → сравнения → not → and → or → ->
~~~

Бинарные операторы группируются слева направо, кроме `->`, который группируется справа налево. Сравнение может содержать не более одного оператора сравнения между арифметическими выражениями.

Контракт `:array-update`. Присваивание `a[i] = v;` обозначает функциональное обновление `a = set(a, i, v)`: порождается новый массив, который присваивается цели `a` (исходный массив не изменяется). В AST это узел `{:node :array-update :target "a" :indices [i] :value v}`; явной подстановки `set(...)` парсер не строит (отдельного прохода desugaring нет, узел является каноническим представлением). Для нескольких индексов `a[i][j] = v;` значение — композиция вложенных обновлений: `a = set(a, i, set(a[i], j, v))`, то есть `a[i]` обновляется как `(a[i])[j] = v`. Индексы хранятся в `:indices` в порядке записи (`[i j]`), а выражения индексов вычисляются в состоянии до присваивания.

При синтаксической ошибке парсер указывает ожидаемую конструкцию, найденный токен и позицию (строка и столбец, нумерация с 1). Внутри блока он пропускает токены до `;`, `}`, `function` или конца файла. Ключевое слово `function` внутри незакрытого блока считается границей: сообщается отсутствующая `}` (один раз для вложенной цепочки блоков), все открытые блоки закрываются без потребления токена `function`, и следующая функция разбирается на верхнем уровне; на верхнем уровне — до следующей функции или конца файла. Восстановление не зацикливается.

## Что не входит в подмножество

- Объявления и ссылки на формулы, кванторы и отдельная полная грамматика предикатов.
- Семантические проверки: объявление имён, типы, число аргументов вызова, границы массивов и возможность изменения параметров.
- Явная подстановка `a[i] = v` в `a = set(a, i, v)`: обновление представлено узлом `:array-update` (см. контракт выше).
## Отклонения от официальной грамматики Funny

- **Необязательное ключевое слово `function`.** В `funny.ru.md` (upstream) функция начинается сразу с идентификатора. Парсер принимает оба варианта: `f(...)` как в upstream и `function f(...)` (совместимость с прежними файлами и тестами). `function` остаётся зарезервированным словом лексера, поэтому имя функции или переменной `function` недопустимо (в upstream это допустимый идентификатор).
- Без `function` начало функции распознаётся по заголовку `имя ( ... )`, за которым идёт `requires` или `returns`: в начале оператора вызов так выглядеть не может. Такой же признак служит границей при восстановлении после пропущенной `}`.
- Локальные переменные в `uses` необязательны к объявлению в примерах проекта (используются неявно), здесь они обязаны быть перечислены в `uses`.
- Формулы, кванторы и предикаты не разбираются (см. выше).
