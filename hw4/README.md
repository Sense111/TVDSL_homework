# HW4: IR, CFG, оптимизации и раскраска

Из аннотированного AST ([HW3](../hw3)) строится трёхадресный код, по нему CFG; над CFG работают локальные оптимизации; по живости строится граф конфликтов временных и жадно раскрашивается. Формат IR описан в [IR.md](IR.md).

## Запуск

Из каталога `hw4`:

```sh
lein test
lein run -m hw4.main examples/sum.funny              # IR до/после, CFG, граф конфликтов, метрики
lein run -m hw4.main examples/sum.funny --cse --dot  # + CSE, + CFG и граф конфликтов в DOT
```

Флаги: `--no-const-prop`, `--no-algebra`, `--no-dce` (выключить оптимизацию), `--cse` (включить CSE, по умолчанию выключен), `--asserts` (компилировать `assert`/`assume` в проверки, по умолчанию игнорируются), `--dot`, `--k N` (сколько регистров; отчёт, какие временные не поместились). Если в программе есть синтаксические или семантические ошибки, они печатаются в stderr с позициями, код выхода 1.

DOT можно отрисовать: `dot -Tpng граф.dot -o граф.png`. Готовый вывод для `sum.funny` с `--cse --dot` — [examples/out/sum_cse.txt](examples/out/sum_cse.txt).

## Как генерируется IR

- Выражения раскладываются во временные `%t1`, `%t2`, …; результат присваивания вычисляется сразу в целевую переменную (`r = x + y*2` даёт `%t1 = y*2; r = x + %t1`).
- Условия (`and`, `or`, `->`, `not`) раскрываются в переходы с ленивым вычислением: булевых значений в IR нет. Поэтому `i < n and a[i] > 0` не читает `a[n]`.
- `a[i] = v` становится `[:aset a a i v]` (функциональное обновление), `length(a)` — `:len`, кортежный вызов — один `:call` с несколькими приёмниками.
- `while` и `if` — метки и `:cjmp`/`:jmp`, `invariant` игнорируется, `assert`/`assume` — только с `--asserts`.

## Оптимизации (все локальные, в пределах блока)

1. **Константы и копии** (`:const-prop`): подстановка известных констант и копий, свёртка `+ - * /` с переполнением по модулю 2^32, `if` с константным условием превращается в `goto`. Деление на константный 0 не сворачивается.
2. **Алгебра** (`:algebra`): `x+0`, `x-0`, `x*1`, `x/1` → копия; `x*0`, `x-x` → 0; сравнение переменной с самой собой → `goto`.
3. **Локальный DCE** (`:dce`): удаляет инструкцию без эффектов, если её результат не живёт дальше (живость считается глобально по CFG, чтобы не удалить значение, нужное в другом блоке). Не удаляются вызовы, деление и обращения к массивам, потому что они могут бросить исключение.
4. **CSE** (`:cse`, по умолчанию выключено): повторное вычисление `+ * neg len []` в блоке заменяется копией, пока операнды не менялись.
5. Недостижимые блоки удаляются после каждого прохода.

Исключения (`/ 0`, индекс вне границ) оптимизации не убирают и не добавляют: это проверяется тестами.

## Раскраска

Живость считается по всему CFG. Узлами графа становятся только временные (`%tN`): временные A и B конфликтуют, если B определяется, пока A жива (для `mov d s` пара `d`–`s` не конфликтует). Раскраска жадная: узлы по убыванию степени, каждому наименьший свободный цвет. Метрики: число инструкций, временных и цветов до и после. С `--k N` выводятся временные, цвет которых не меньше N (кандидаты в spill); код spill не генерируется.

## Тесты

`lein test`: 45 тестов, 1008 проверок.
- `ir_test`, `cfg_test`, `interp_test` — генерация, блоки, живость, интерпретатор;
- `opt_test` — по каждому проходу точный ожидаемый IR; примеры курса; **сравнение результатов до и после оптимизаций** (`interp`) для 12 программ при всех 16 комбинациях флагов; 200 случайных выражений, включая границы `int`; ошибки времени исполнения сохраняются;
- `regalloc_test` — корректность раскраски на ручных графах, программах Funny и 40 пересекающихся временных.
